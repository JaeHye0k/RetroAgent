# 회고 에이전트

텔레그램에 생각날 때마다 줄글을 던져두면, 하루 끝에 모아서 노션 일간 회고 템플릿 형태로 정리해준다. 미리보기를 확인하고 승인하면 그날 페이지에 들어간다.

```
텔레그램 조각글  →  큐에 쌓임  →  23:00 정리  →  미리보기 승인  →  노션 일간 회고
                                    ↑
                                  /now 로 언제든
```

## 어떻게 굴러가는가

| 구성 | 역할 |
|---|---|
| `src/index.js` | 텔레그램 long-polling + 30초 스케줄러 틱 |
| `src/compose.js` | `claude -p` 를 불러 조각글을 구조화 JSON 으로 변환 |
| `src/notion.js` | 노션 REST API — 페이지 찾기/만들기, 섹션에 블록 끼워넣기 |
| `src/pipeline.js` | 정리 → 미리보기 → 승인 → 저장 상태 머신 |

**LLM 은 텍스트를 JSON 으로 바꾸는 일만 한다.** 노션 API 호출, 페이지 탐색, 블록 삽입 위치 계산은 전부 일반 코드가 처리한다. 그래서 실패 지점이 좁고 단위 테스트가 가능하다.

외부 의존성은 없다. Node 내장 `fetch`, `--env-file`, `node:test` 만 쓴다.

> 구조도와 데이터 흐름 다이어그램은 [`docs/architecture.html`](docs/architecture.html) 에 있다. 브라우저로 열면 된다.

## 셋업

### 1. 텔레그램 봇 만들기

텔레그램에서 [@BotFather](https://t.me/BotFather) 에게 `/newbot` → 이름과 username 을 정하면 `123456789:AA...` 형태의 토큰을 준다.

### 2. `.env` 만들기

```bash
cp .env.example .env
```

`TELEGRAM_BOT_TOKEN` 을 채운다. `TELEGRAM_CHAT_ID` 는 아직 모르니 아무 숫자나 둔다.

### 3. 노션 회고 DB 준비하기

데이터베이스에 이 세 속성이 있어야 한다. 이름까지 그대로여야 한다.

| 속성 | 타입 | 비고 |
|---|---|---|
| `이름` | 제목 | `2026.07.26 일간 회고` 형태로 채워진다 |
| `날짜` | 날짜 | 회고 날짜 |
| `주기` | 선택 | `일간` 옵션이 있어야 한다 |

페이지 안쪽은 비워둬도 된다. 첫 저장 때 이 뼈대를 만든다.

```
## 오늘 한 일          (heading 2, 글자색 보라)
> 오늘 있었던 일·활동을 사실 위주로 간단히 적습니다.   (인용, 블록색 회색)
---
## 한 줄 배움 / 감정    (heading 2, 글자색 초록)
> 오늘 배운 것, 느낀 감정을 한 줄로 남깁니다. 감정이라면 그 원인도 함께 떠올려봅니다.
```

섹션 이름을 바꾸고 싶으면 [`src/blocks.js`](src/blocks.js) 의 `SECTIONS` 를, 속성 이름은 [`src/notion.js`](src/notion.js) 의 `PROPS` 를 고친다.

### 4. Notion Integration 만들기

1. [notion.so/my-integrations](https://www.notion.so/my-integrations) → **New integration** → Internal
2. 발급된 `ntn_...` 토큰을 `.env` 의 `NOTION_TOKEN` 에 넣는다
3. **회고 DB 를 이 integration 에 공유한다** — 노션에서 DB 열고 우상단 `···` → **연결** → 방금 만든 integration 선택

이 3번이 빠지면 토큰이 맞아도 `object_not_found` 가 난다.

`NOTION_DB_ID` 는 회고 DB 의 URL 을 그대로 붙여넣어도 된다.

### 5. 연결 확인

봇에게 텔레그램으로 아무 메시지나 하나 보낸 뒤:

```bash
npm run whoami
```

봇 연결, 실제 `chat id`, 노션 DB 접근 가능 여부, 필요한 속성(`이름`/`날짜`/`주기`) 존재를 한 번에 점검한다. 출력된 chat id 를 `.env` 의 `TELEGRAM_CHAT_ID` 에 넣는다.

### 6. 띄우기

```bash
npm start
```

잘 돌면 로그인할 때마다 자동으로 뜨도록 등록한다:

```bash
npm run install-agent
```

## 쓰는 법

생각날 때마다 봇에게 그냥 보낸다. 👌 리액션이 붙으면 큐에 들어갔다는 뜻이다.

| 명령 | 동작 |
|---|---|
| `/now` | 지금까지 쌓인 조각을 바로 정리 |
| `/queue` | 큐에 쌓인 조각 보기 |
| `/status` | 큐 개수, 정리 시각, 오늘의 회고 날짜 |
| `/undo` | 마지막 저장 되돌리기 |
| `/help` | 도움말 |

23:00(기본값)이 되면 그날 조각을 모아 정리해 미리보기를 보낸다. 버튼은 네 개다.

- **✅ 저장** — 그날 일간 회고 페이지에 넣는다. 페이지가 없으면 템플릿 뼈대와 함께 새로 만든다.
- **🔄 다시 정리** — 같은 조각으로 다른 정리안을 받는다.
- **📄 원문** — 정리 전 원문 조각을 본다.
- **❌ 취소** — 저장하지 않는다. 조각은 큐에 그대로 남는다.

## 설계상 알아둘 것

**조각글은 유실되지 않는다.** 자동 정리가 실패하면 원문을 그대로 `미분류` 항목으로 넣는 폴백으로 내려간다. 노션 저장이 실패하면 큐를 비우지 않는다. 큐에서 조각을 뺄 때도 삭제가 아니라 `data/archive/<날짜>.jsonl` 로 옮긴다.

**회고 날짜는 "지금"이 아니라 조각이 쓰인 시각으로 정한다.** 각 조각의 `ts` 로 날짜를 묶으므로, 큐에 며칠치가 섞여 있어도 각자 맞는 날짜의 페이지로 간다.

`DAY_CUTOFF_HOUR`(기본 4시) 이전에 쓴 조각은 전날 몫이다. 새벽 2시에 쓴 회고를 다음 날 페이지에 넣고 싶지 않기 때문이다.

**맥북을 덮고 자도 날짜가 밀리지 않는다.** 월요일 밤에 덮고 화요일 아침에 열면, 큐에 남은 월요일 조각은 월요일 페이지로 들어간다. 며칠 밀렸으면 가장 오래된 날짜부터 하루씩 미리보기가 온다 — 승인하면 다음 날짜가 이어서 온다. 임계 시각이 아직 안 된 오늘 몫은 섞이지 않는다.

`/status` 로 어느 날짜가 몇 개 밀려 있는지 볼 수 있다. `/now` 는 임계 시각을 무시하고 가장 오래된 날짜부터 정리한다.

**모든 네트워크 호출에 타임아웃이 있다.** 잠자기에서 깨어날 때 소켓이 죽었는데도 에러가 나지 않고 매달리면, 재시도 로직이 발동하지 않아 조각을 못 받는 상태로 조용히 남는다. 텔레그램·노션 요청 모두 `AbortSignal.timeout()` 으로 끊고, 폴링은 백오프 재시도로, 노션은 재시도 대상으로 이어진다.

**남이 내 회고에 쓸 수는 없다.** `TELEGRAM_CHAT_ID` 와 일치하지 않는 chat 의 업데이트는 전부 무시한다.

**정리는 이미 로그인된 `claude` CLI 인증을 그대로 쓴다.** 구독으로 로그인해 뒀다면 Anthropic API 종량 과금이 따로 붙지 않는다. `--safe-mode` 로 돌기 때문에 CLAUDE.md·훅·MCP·플러그인이 개입하지 않는다.

## 정리 품질 손보기

정리 규칙은 [`prompts/compose.md`](prompts/compose.md) 에 있다. 코드와 분리해뒀으니 여기만 고치면 된다.

고친 결과는 텔레그램·노션 없이 바로 확인할 수 있다:

```bash
node scripts/dry-run.js
```

내장 샘플로 실제 `claude` 를 호출해 미리보기 텍스트와 만들어질 노션 블록을 출력한다. 내 실제 메모로 시험하려면 한 줄에 조각 하나씩 담은 파일을 넘긴다:

```bash
node scripts/dry-run.js my-notes.txt
```

## 운영

```bash
tail -f data/logs/agent.log          # 로그
launchctl print gui/$(id -u)/com.retro-agent.daily | head -20   # 상태
npm run uninstall-agent              # 자동 실행 해제
```

`data/` 안에 상태가 모여 있다.

| 파일 | 내용 |
|---|---|
| `queue.jsonl` | 아직 정리되지 않은 조각 |
| `archive/<날짜>.jsonl` | 정리를 마친 조각의 원문 |
| `pending.json` | 승인 대기 중인 정리안 |
| `offset.json` | 텔레그램 업데이트 커서 |
| `digest-state.json` | 자동 발송을 마친 회고 날짜 목록 |
| `last-write.json` | `/undo` 대상 |

## 테스트

```bash
npm test
```

노션·텔레그램·claude 를 전부 가짜로 바꿔 154개 테스트를 돌린다. 눈여겨볼 만한 것들:

- 조각의 ts 로 날짜를 묶는지, 새벽 조각이 전날로 가는지, 월·연 경계 (`schedule.test.js`)
- 월요일 밤에 덮고 화요일 아침에 열었을 때 월요일 페이지로 가는지 (`pipeline.test.js`)
- 며칠 밀렸을 때 오래된 날짜부터 하나씩 처리하는지, 아직 임계 시각이 안 된 오늘 몫이 섞이지 않는지 (`pipeline.test.js`)
- 죽은 소켓에 매달리지 않고 끊는지, long-poll 을 오인해 끊지 않는지 (`telegram.test.js`)
- 섹션 헤딩 아래 정확한 위치 계산, 구분선·다음 헤딩 경계 (`notion.test.js`)
- 정리 실패 시 폴백, 형식 오류 재시도 (`compose.test.js`)
- 저장이 중간에 실패한 뒤 재시도할 때 앞 섹션이 중복 삽입되지 않는지 (`pipeline.test.js`)
- 정리하는 동안 들어온 조각이 저장 후에도 큐에 남는지 (`pipeline.test.js`)
